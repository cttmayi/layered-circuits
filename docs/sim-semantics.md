# 仿真语义规范（sim-semantics.md）

> 本文件是《逐层电路》仿真内核的**唯一权威定义**。
> 任何与代码不一致的地方以本文件为准；改动语义必须先改本文件 + 补测试。
> 实现：`packages/sim-core`（纯 TS，零 DOM 依赖）；测试：`packages/sim-core/test`。

---

## 1. 为什么是「开关级」而不是 SPICE

GDD 0.2 锁定「纯逻辑仿真、无实物模拟」，所以：

| 方案 | 结论 |
|---|---|
| 模拟电路仿真（MNA + 牛顿迭代 / SPICE） | ❌ 收敛失败、性能差、玩家看不懂「仿真不收敛」这种反馈 |
| **开关级数字仿真 + 强度语义（本作采用）** | ✅ 快、确定、错误可解释（浮空/短路/多驱动/振荡） |
| 直接给门级原语 | ❌ 违背「从三极管搭门」的核心卖点 |

三极管、电阻、二极管被抽象成**通路元件**，节点电平由「逻辑值 + 驱动强度」共同决定。

## 2. 信号编码

```
信号 = 0                    → 高阻 Z（该节点当前没有任何驱动）
信号 = (强度 << 2) | 逻辑值  → 有驱动

逻辑值：0 = 低，1 = 高，2 = X（冲突 / 未知）
强度：  1 = WEAK（电阻等弱驱动），2 = STRONG（三极管/二极管导通、电源轨、关卡输入引脚）
```

对外读取时映射为 `0 | 1 | 'X' | 'Z'` 四种逻辑结果（`toLogic()`）。面板上应分别展示为
「低 / 高 / 不确定（红） / 悬空（黄）」。

时间单位一律 **皮秒整数（ps）**：禁用浮点参与逻辑判定，保证仿真确定性与服务端可重放。

## 3. 元件模型

| 元件 | 引脚 | 信号延迟 | 传递能力上限 | 说明 |
|---|---|---|---|---|
| NPN 三极管 | c / b / e | 1.0 ns | STRONG | 受控双向通路；基极只读，不吸收电流 |
| 电阻 | a / b | 0.5 ns | **WEAK** | 双向通路，但永远只能提供弱驱动 |
| 二极管 | a(阳极) / k(阴极) | 0.8 ns | STRONG | **单向**导通：电流只能阳极 → 阴极 |
| 电容 | a / b | —— | —— | **不参与逻辑仿真**，只计入成本（见 §8） |
| 电源轨 VCC / GND | p | 0 | STRONG | 免费端口，不计成本（GDD 的 4 种计费元件里没有电源） |
| 关卡输入引脚 | p | 0 | STRONG | 由关卡激励驱动；默认 Z（悬空，便于暴露未连接） |
| 关卡输出引脚 | p | 0 | —— | 只观察，不驱动 |

### 3.1 三极管（NPN）

- 基极读逻辑值：`1` → 导通；`0` → 截止；`Z`（悬空）→ **截止** + 警告
  （不按 X 处理，否则一个忘记接线的基极会让整片电路到处是 X，噪音大于信息量）；
- `X` → 通断未知：向两端注入**弱 X**（真实强驱动仍能压过它）；
- 导通时**双向**（集电极↔发射极互为通路）：这是 RTL 下拉网络与串联与非门能工作的前提。

### 3.2 二极管

导通条件（数字抽象）：`阳极确定为 1` 且 `阴极不是确定为 1`（阴极为 0 / Z / X 均可）。
反向一律不导通 —— 这就是 GDD 说的「单向导通 + 逻辑隔离」：
阴极高电平时不会反向倒灌阳极，所以输出不会回灌到输入。

### 3.3 通路元件的统一传递规则（关键）

> **任何通路元件（电阻 / 三极管 / 二极管）只向「外部驱动更弱」的一侧传递电平，
> 强度取 `min(强侧强度, 元件能力上限)`；两侧都没有外部驱动时谁都不驱动。**

其中「外部驱动」= 该节点上**排除本元件自身贡献**之后的归约结果（`resolveExcluding`）。

为什么必须这样？两个真实发生过的反面例子（都用测试锁定了）：

1. **伪稳态（浮空孤岛）**：RTL 与非门里 Q1/Q2 串联，中点 MID 原本被 Q2 强拉到 0。
   当某个输入从 1 变 0、Q2 截止后，MID 变成浮空。若三极管无条件双向传递，
   MID 和 OUT 会通过 Q1 互相「自证」一个强 0，数字仿真里永远锁死为 0 ——
   而真实电路会被上拉电阻充电拉高（RC 充电）。加入「只压向更弱一侧」后，
   浮空侧没有外部驱动，就不会自我维持电平，MID 正确回到 1。
2. **同强度对拉**：两侧强度相同且电平相反 → 互相交换电平 → 节点得到相反的两个弱驱动 → **X**。
   这正是「电阻分压不确定」的语义来源，玩家会看到「电阻分压，结果不确定」而不是一个假的高/低。

### 3.4 节点归约

```
有 STRONG 驱动 → 取该值；多个 STRONG 且值不同 → X（并报 drive-conflict 错误 = 短路/多驱动）
无 STRONG、有 WEAK → 取该值；多个 WEAK 且值不同 → X（resistive-tie 警告 = 分压不确定）
全部为 Z → Z（悬空）
```

注意：**逻辑判定不区分强度**。强度只用于「谁压过谁」。因此 RTL 里
「上拉电阻给出的弱 1」与「三极管给出的强 1」在真值表上都是 1，但被强 0 拉低时结果不同。
这既符合真实 RTL，也让「低成本极简电路 vs 高成本稳定电路」的取舍有物理依据。

## 4. 两种调度模式（一套求值逻辑）

| | 新手科普模式 `mode: 'logic'` | 硬核工程模式 `mode: 'timing'` |
|---|---|---|
| 延迟 | 全部按 0（忽略） | 按上表加载（ps 整数） |
| 调度 | 同刻 FIFO 队列（同刻去重） | 最小堆事件队列 |
| 收敛判据 | 迭代到无变化 | 事件队列排空 / 到达指定时刻 |
| 组合环 | 超过迭代上限 → 报 `unstable` 并列出波动最剧烈的节点 | 表现为持续振荡；超过事件上限 → 报错中止 |
| 时序违例 | 不检查 | 检查（M2 起：空翻/竞争冒险、建立/保持时间实测） |
| 上电建立 | 所有元件在 t=0 迭代到收敛 | 只有电源/引脚在 t=0 建立，其余按各自延迟逐级传播 |
| 波形 trace | 记录每次节点变化，时刻恒为 0 | 记录每次节点变化，时刻是真实事件时刻 |
| 默认迭代/事件上限 | `max(2000, 50 × 元件数)` | 20,000,000 事件 |

两种模式共用同一份元素求值代码，只有调度器不同 —— 因此「新手模式下能跑通的电路，
在硬核模式下不会因为语义不同而变成另一种结果」，差异只体现在延迟上。

**确定性保证**：事件同刻按入队序号（`seq`）决胜，节点、元素的遍历顺序固定，
不使用浮点参与判定 —— 同一网表重放结果逐位一致（服务端校验排行的前提）。

### 4.1 激励的施加时刻必须确定（M2）

时序模式里 `setInput` 是把事件排在 `this.timePs`（= 上一次事件发生的时刻）上。
如果关卡向量直接用它，激励的落点就会取决于上一个向量里电路的内部节奏
（2000ps 还是 2001ps 全看元件延迟），波形窗口、建立/保持测量都会跟着漂。

因此 M2 起时序模式一律用 `setInputAt(port, value, atPs)`：先把时钟推到给定时刻
（队列空了也要推），再让激励在该时刻生效。**向量的时间窗口 = [上一个窗口终点, 本窗口终点]**，
判定、跳变计数、波形竖线三者共用这一个窗口定义。

### 4.2 波形（信号轨迹）

`Simulator` 在 `trace: true` 时把每次节点变化记成三组平行数组（时刻 / 节点 / 信号），
`toWaveform()` 把它整理成「每个网络一条阶梯曲线」，`transitionsIn(wave, node, from, to)`
数某个窗口内的跳变次数。判定用的就是这份数据，所以**面板上画出来的波形就是判定的依据**。

### 4.3 空翻 / 竞争冒险怎么判

时序关卡可以声明 `checks.maxGlitches`：某个窗口内任一输出端口的跳变次数超过它，
就是「时钟翻转期间输出跟着抖」。约定第 1 个向量（含上电建立过程）不参与统计。

### 4.4 建立 / 保持时间怎么测（M2）

不查数据手册，**用真仿真扫**（`measureSetupHold`）：

1. 基线：把 D 固定为 0 → 时钟沿 → 读到 0；再把 D 固定为 1 → 时钟沿 → 读到 1；
   然后**时钟沿之后**才改数据，输出必须保持 —— 三条都成立才算「边沿触发」，
   否则（例如 D 锁存器是透明的）直接判定「无法测量」，而不是给个假数字。
2. 建立时间：数据跳变放在 `时钟沿 − offset`，offset 从 0 起按步长（默认 500ps）往后扫，
   第一个还能正确锁存的位置就是建立时间。
3. 保持时间：数据跳变放在 `时钟沿 + offset`，第一个还能锁住旧值的位置就是保持时间。

采样点取「时钟沿之后 `min(时钟周期, max(2 × 关键路径, 20ns))`」，物理含义是
**输出必须在本时钟周期内稳定**。结果是**最坏情况上界（误差 ≤ 一个步长）**，
UI 上如实标注步长。

**已知模型偏差**：本引擎各元件延迟是离散常量，数据路径与阻塞路径的先后完全由事件顺序决定，
因此在 500ps 精度内实测到的建立时间常常是 0 —— 真实硅片上主从触发器会有几 ns 的建立时间。
保持时间则是有意义的（参考 D 触发器实测 ≈ 1ns）。这条偏差记在 §8 局限里。

## 5. 诊断（面向玩家的错误提示）

| 诊断 | 级别 | 触发条件 | 玩家看到的话 |
|---|---|---|---|
| `drive-conflict` | error | 节点上 ≥2 个强驱动冲突 | 「存在 N 个强驱动互相冲突（短路/多驱动）」 |
| `resistive-tie` | warning | 节点上 ≥2 个弱驱动对拉 | 「电阻分压，结果不确定」 |
| `floating-input` | warning | 三极管基极悬空（**仿真停下来时仍悬空**才报；时序模式建立过程中途的悬空不报） | 「基极悬空，按截止处理」 |
| `unstable` | error | 逻辑模式未收敛 / 事件数超限 | 「组合环/振荡」+ 波动最剧烈的节点 |
| `cap-ignored` | info | 电路里有电容 | 「电容仅计入成本，不参与逻辑仿真」 |

未连接引脚（编译期，见 `@lc/compiler`）：`unconnected-pin`（warning）、
`unknown-module`（error）、`depth-exceeded` / `size-exceeded`（error）。

## 6. 参考电路（语义自证 + 回归测试）

`packages/sim-core/test` 与 `packages/compiler/test` 里的电路就是本规范的活文档：

| 电路 | 实现 | 成本 | 验证点 |
|---|---|---|---|
| RTL 非门 | Q1 共射反相级 + Q2 射极跟随器输出级 + 3 电阻 | **7**（2×2 + 3×1，与 GDD 2.2.2 一致） | 真值表；输出「强 1 / 弱 0」；2.5ns 延迟（0.5+1.0+1.0） |
| RTL 与非门 | 两个 NPN 串联 + 3 电阻 | 7 | 真值表；串联导通拉低；浮空中点不自锁 |
| SR 锁存器 | 两个与非门交叉耦合 | 14（4 三极管 + 6 电阻） | 置位/保持/复位/保持；行为判定为时序电路 |
| 二极管与门 | 阳极并联 + 上拉，阴极接输入 | 2 二极管 + 1 电阻 | 单向导通把阳极压到低电平 |
| 二极管或门 | 阳极接输入 + 下拉，阴极并联 | 同上 | 强侧把阴极拉高 |
| 二极管 ROM 单元 | 字线 → 二极管 → 位线（位线有下拉） | 1 二极管 + 1 电阻 | 字线选中为 1、未选中为 0 |

> 注意：GDD 2.2.2 写的「非门 = 2 三极管 + 3 电阻」指的是**带输出级**的实现
> （单管共射反相器只需 1 三极管 + 2 电阻）。若两个三极管都接成反相级，
> 电路实际是**缓冲器**而不是非门 —— 这一点已用测试固化，避免后续关卡内容按错的直觉设计。

## 7. 成本与时序的语义边界

- **成本**：只在封装那一刻递归展开到 4 种基础元件并缓存（`UnitCounts`），
  运行期查表点积，不在仿真热路径里递归（GDD 6.2）。电源轨、输入输出引脚成本为 0。
- **时序**：「模块端口延迟矩阵」由**同一套时序仿真实测**（每个输入做 0→1 / 1→0 翻转，
  取输出最后一次变化的时刻），而不是图论静态时序分析。
  原因：开关级模型里电阻/三极管/二极管都是双向通路，图论最长路会产生大量伪环，
  容易得出「组合电路被判定为时序电路」「关键路径为 0」这类错误结论。
  实测法的结果与硬核模式仿真完全一致（面板上显示的延迟就是仿真器真的延迟）。
- **是否时序电路**：行为判定 —— 同一个激励向量在「冷启动」与「经历过别的激励之后」
  输出不同 ⇒ 有记忆 ⇒ 时序电路。探测向量包含全 0 / 全 1 / 交替 / 逐位单独置 1。

## 8. 已知局限与后续计划（诚实清单）

| 局限 | 影响 | 计划 |
|---|---|---|
| 无 RC 充电模型（不做模拟充放电） | 极端浮空节点的建立时间不真实 | 用 §3.3 的传递规则规避伪稳态；M2 若需要再做惯性延迟细化 |
| 无 Vbe 压降 / 饱和压降 | 射极跟随器输出被理想化为满幅 | 已在文档与 UI 上按「理想开关」表述 |
| 无比值逻辑（电阻比值判断高低） | 同强度对拉判为 X，不做分压计算 | 有意为之：X 是可解释的教学反馈；后续可加「可选严格比值模式」|
| 电容不参与仿真 | 时钟不能由玩家用 RC 振荡电路产生 | 时钟按关卡提供的免费端口建模；玩家搭的振荡环由编译器识别折叠为时钟源（M2） |
| 无扇出限制、无短路电流/功耗模型 | 真实 RTL 的扇出问题不体现 | 硬核模式后续可选加「扇出上限」严格档 |
| 建立时间实测常为 0（离散延迟模型，数据路径总赢得竞争） | 真实硅片的建立时间无法复现；保持时间与空翻判定仍有效 | 需要更细的惯性延迟/阈值模型；当前在 UI 与文档上如实标注 |
| 整机规模仍靠递归展开 | 256×8 RAM 这种规模会慢 | M4 改为「模板编译一次 + 实例化多次」的黑盒执行（Tech-Plan 2.3） |

## 9. 变更流程

1. 改语义 → 先改本文件（写清物理动机 + 反例）；
2. 在 `packages/sim-core/test` 加能复现新旧差异的用例；
3. 跑 `pnpm check`（typecheck + lint + 全部测试）全绿；
4. 若涉及关卡内容，同步更新 `referenceSolution` 与预算（`optimalHalf`）。
