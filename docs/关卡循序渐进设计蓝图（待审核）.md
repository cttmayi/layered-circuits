### 4 个跳变断点

| 断点 | 跳变 | 本质问题 |

| ① 或非门 → 异或门 | 元件 7 → 22，成本 20 → 80 | 第一次出现"多级组合逻辑"（先算中间值、再合并）就是最难的异或门 |

## 二、设计原则

1. **小步走**：每关只教一个新概念，元件/成本平滑增长，不出现翻 3 倍的陡坡。
2. **概念复用**：每关教的东西必须在后续关反复出现——
   - 控制位选择（mux 的 sel）→ ALU 的 op 位
   - 使能门控（门控 SR 的 en）→ D 锁存器 → 触发器的时钟
   - 模块级联（2 位加法器）→ 4 位 → 8 位
   - 可控取反（减法器）→ ALU 的加/减开关
3. **模块化导向**：教"搭好 → 封装 → 复用"。大电路靠拼模块，不靠手搭。
4. **契约兼容**：新增关全部 **RTL 单规格**（不加 familyRefs 契约变体），4 契约判定体系零改动；新增关的模块白名单只列玩家已封装的门。
5. **线性解锁不变**：新关插入 ALL_LEVELS 数组正确位置，`isLevelUnlocked`（看前一关 cleared）自动衔接——玩家必须过新关才能继续。

## 三、新增关卡详细设计

### 新关 A：s1-mux2 二选一选择器（补断点 ①）

| 项 | 内容 |
|----|------|
| **插入位置** | s1-nor（或非门）之后、s1-xor（异或门）之前 |
| **标题** | 二选一选择器 |
| **解锁链** | 或非门 → 选择器 → 异或门（自动衔接） |
| **端口** | a / b / sel（1 位输入），y（1 位输出） |
| **功能** | sel=0 → y=a；sel=1 → y=b |
| **参考解** | 1 个非门 + 3 个与非门：y = ¬(¬(¬sel·a) · ¬(sel·b))（强驱动，可级联） |
| **标准答案** | 成本 ≈ 72（非门 12 + 3×与非门 20）；元件 ≈ 26 |
| **模块白名单** | 只许【非门】【与非门】（与异或关同一思路，教"与非门万能"） |
| **难度定位** | 或非门 20 → **72** → 异或门 80：72 是"两级组合"的第一课，异或 80 只是同样的活 ×1.1 |

**教学点**：
- **控制位选择**：sel 决定信号走哪条路——"选择器就是开关"。
- **两级组合逻辑**：先算 ¬sel 分支（第一级），再把两条分支合并（第二级）——异或门的"先算再合"完全同构，玩家在异或关会惊呼"这不就是上关干过的事"。
- **伏笔**：sel 位 = 后面 ALU 的 op 位（"选加法还是减法"），教学文案明示。

**真值表向量**：
| sel | a | b | y | 备注 |
|-----|---|---|---|------|
| 0 | 0 | 1 | 0 | 选 a |
| 0 | 1 | 0 | 1 | 选 a |
| 1 | 0 | 1 | 1 | 选 b |
| 1 | 1 | 0 | 0 | 选 b |

### 新关 B：s2-gated-sr 门控 SR 锁存器（补断点 ②）

| 项 | 内容 |
|----|------|
| **插入位置** | s2-sr-latch（SR 锁存器）之后、s2-d-latch（D 锁存器）之前 |
| **标题** | 门控 SR 锁存器 |
| **解锁链** | SR 锁存器 → 门控 SR → D 锁存器 |
| **端口** | s / r / en（1 位输入），q / qn（1 位输出） |
| **功能** | en=0：锁死保持；en=1：s/r 生效（高有效：s=1 置位 q=1，r=1 复位 q=0） |
| **参考解** | SR 锁存器（2 或非门）+ 门控（2 与门：en∧s、en∧r） |
| **标准答案** | 成本 ≈ 56（40 + 2×8）；元件 ≈ 20 |
| **模块白名单** | 只许【或非门】【与门】【非门】 |
| **难度定位** | SR 锁存器 40 → **56** → D 锁存器 92：56 是"使能"第一课 |

**教学点**：
- **使能门控**：en=1 门才开（允许更新），en=0 门锁死（保持）——**存储器的灵魂**：没有 en，锁存器没法"选时机"更新。
- **伏笔**（文案明示）："下一关的 D 锁存器，就是把这里的 s、r 两条线合成一条 d 线——d 和 ¬d 天然互反，正好喂进门控的两个与门。"
- 时序概念：向量按"置位 → 松手保持 → 关门保持"顺序验证（沿用 SR 锁存器的测法）。

**向量（顺序执行，验证保持）**：
| s | r | en | q | 备注 |
|---|---|----|---|------|
| 1 | 0 | 1 | 1 | 门开，置位 |
| 1 | 1 | 1 | 1 | 松手保持 |
| 1 | 1 | 0 | 1 | 关门，保持 |
| 0 | 1 | 1 | 0 | 门开，复位 |
| 1 | 1 | 0 | 0 | 关门，保持 |

**文案强化（顺带，零成本）**：s2-sr-latch 教学文案补一段"为什么需要记忆"——修表铺叙事：顾客把表放你柜台，你得记着"这只表调过没有"，不能一断电就忘。

### 新关 C：s3-adder-2 两位加法器（补断点 ③）

| 项 | 内容 |
|----|------|
| **插入位置** | s3-full-adder（全加器）之后、s3-adder-4（4位加法器）之前 |
| **标题** | 两位加法器 |
| **解锁链** | 全加器 → 两位加法器 → 4位加法器 |
| **端口** | a[1:0] / b[1:0]（2 位总线输入），y[1:0]（2 位输出），cout（1 位） |
| **功能** | a + b → y，溢出进 cout（总线数值判定，沿用加法器"向量=代表性算式"测法） |
| **参考解** | 2 个全加器串联：低位 cout → 高位 cin，最低位 cin 接地 |
| **标准答案** | 成本 = 360（= 2×全加器 180）；元件 ≈ 94 |
| **模块访问** | 'all'（教学点就是"拖 2 个【全加器】模块串起来"，手搭反而贵） |
| **难度定位** | 全加器 180 → **360** → 4位加法器 720：360 是"串 2 个"第一步 |

**教学点**：
- **模块级联**：第一次把"一个模块"复制成 N 份串联。"串 2 个会了，串 4 个、串 8 个只是同一件事重复——下一关 4 位加法器就是再串 2 个。"
- **进位链**：低位 cout 喂高位 cin——进位链是加法器最长的信号路径（对应延迟线概念：越串越长）。
- **总线端口**：第一次 2 位总线（半加器/全加器是 1 位），为 4/8 位总线铺路。

**向量示例**：
| a | b | y | cout | 备注 |
|---|---|----|------|------|
| 0 | 0 | 0 | 0 | 0+0 |
| 1 | 1 | 2 | 0 | 1+1 |
| 2 | 3 | 5 | 0 | 2+3 |
| 3 | 3 | 6 | 1 | 3+3 溢出进位 |

### 新关 D：s3-sub-4 四位减法器（补断点 ④）

| 项 | 内容 |
|----|------|
| **插入位置** | s3-adder-8（8位加法器）之后、s3-alu（简易ALU）之前 |
| **标题** | 四位减法器 |
| **解锁链** | 8位加法器 → 四位减法器 → 简易ALU |
| **端口** | a[3:0] / b[3:0]（4 位总线输入），y[3:0]（4 位输出） |
| **功能** | a − b → y（补码；a ≥ b 时输出正确差。向量只给 a ≥ b 的算式） |
| **参考解** | 4 个异或门（当"可控取反器"：b⊕1 = ¬b）+ 4 位加法器（最低位 cin=1 即 +1）：y = a + ¬b + 1 |
| **标准答案** | 成本 ≈ 1040（4×80 + 720）；元件 ≈ 270 |
| **模块访问** | 'all'（拖【异或门】和【加法器】拼） |
| **难度定位** | 8位加法器 1440 → **1040** → ALU 1040：成本回落因为只做 4 位；新概念（补码/取反开关）是这关的重点 |

**教学点**：
- **补码减法**：a − b = a + ¬b + 1——"减法不是新电路，是加法器加一个取反开关"。
- **异或门 = 可控取反器**：x⊕1 = ¬x、x⊕0 = x——异或门当开关用，这是 Stage 1 异或门的**第二次生命**（第一次是求和，这次是取反）。
- **伏笔**（文案明示）："下一关的 ALU，就是把这个取反开关的'开/关'做成一条 op 位输入线——op=0 直通（加法），op=1 取反（减法）。你搭的减法器，已经是 ALU 的一只脚了。"

**向量示例**（全部 a ≥ b）：
| a | b | y | 备注 |
|---|---|---|------|
| 5 | 2 | 3 | 5−2 |
| 9 | 7 | 2 | 9−7 |
| 15 | 1 | 14 | 15−1 |
| 12 | 12 | 0 | 12−12 |

## 五、实现计划（审核通过后执行）

1. **参考解**：在 `packages/content/src/references-ari.ts`（或新增 references 段）用 DesignBuilder 写 4 个参考解：
   - mux2：复用 `nandInto` 模式（非门 + 3 与非门）
   - gated-sr：或非门互锁 + 2 与门
   - adder-2：复用 `fullAdderRef` 的与非门结构 ×2 串联
   - sub-4：复用 `xorInto`（b⊕1）+ `adder4Ref`（cin=1）
2. **关卡定义**：在 `levels.ts` / `levels-seq.ts` / `levels-ari.ts` 插入 `parseLevel` 对象，位置按上文表格；`optimalHalf` = 参考解实测成本（跑快照脚本校准，不用估算值）。
3. **延迟线**：`timingBudgetPs` = 参考解实测关键路径 × 2（沿用现行快照工具，保证"参考解一键出答案 = 3 星"契约）。
4. **moduleAccess**：mux2 / gated-sr 用 `'listed'` 白名单（只列玩家已封装的门）；adder-2 / sub-4 用 `'all'`。
5. **教学关变体**：新关均不加 familyRefs（RTL 单规格，4 契约共用同一规格）。
6. **测试**：每关补"参考解过关 + costHalf = optimalHalf + 3 星"断言（沿用 family-refs.test 模式）；现有 191 测试全部保持绿色。
7. **解锁链**：插入数组位置后由 `isLevelUnlocked` 自动衔接，无需改逻辑。

## 七、诚实局限

1. 新关 optimal / 延迟线均为**估算**，实现时以参考解实测校准（本蓝图已按"参考解成本 = 标准答案"契约设计，实测后数值只会有 ±10% 级微调，不改变难度阶梯结论）。
2. 新关只有 RTL 单规格：TTL/CMOS 玩家玩到新关时，判定规格与 RTL 相同（元件集仍允许 npn/res/dio），不会出现"契约参考解 vs 关卡规格"不一致——但**不会**有 TTL/CMOS 专属参考解与延迟线（后续如要，按 familyRefs 机制补）。
3. 本蓝图未改 Stage 1/2 现有关的内容与顺序（除文案强化），已通关存档的解锁链不受影响。

## 八、简易计算器设计（最终目标升级）

> 用户拍板（verbatim 归纳）：**真实计算器**——有按键输入、有屏幕显示、只支持两位数、只支持加法。
> 实现决策链：接受新增七段数码管 → 采用「BCD 转二进制」架构（先转二进制、用二进制加法器、再转回 BCD 显示）→ 电平端口当按键 → **新增按钮元件（按下改变电平、松手自动弹起）**。

### 8.1 机制设计（判定零改动）

| 新机制 | 实现模型 | 判定影响 |
|--------|----------|----------|
| **七段数码管（屏幕）** | 关卡**输出端口**声明 `display: 'segment'` → 画布把该端口渲染成七段数码管图形，按端口值（BCD 0-9）点亮段 | 无（还是普通输出端口数值判定） |
| **按钮（按键）** | 关卡**输入端口**声明 `button: true` → 画布渲染成按钮（教学关 sprite 已有），按住 → 电平 1、松开归 0（瞬时） | 无（还是普通输入端口，向量给 0/1） |
| **BCD 输入** | a、b 各 8 位（十位+个位各 4 位 BCD，0-99 真十进制） | 无（总线端口，沿用加法器测法） |

这样**判定器/仿真器/成本系统零改动**，只动：schema 端口 schema（加可选字段）+ 画布渲染（数码管绘制）+ 点击交互（瞬时弹起）。

### 8.2 计算器关卡链（新增 4 关，接在 ALU 之后）

```
… 8位加法器 → ALU（现有）
→ E: s3-bcd2bin  两位 BCD → 二进制（组合）
→ F: s3-bin2bcd  二进制 → 两位 BCD（组合）
→ G: s3-reg-8    八位寄存器（clk 边沿锁存，结果「留下」）
→ H1: s3-or-chain 多输入或门（或 = 二极管并联扩展，编码器 or 矩阵的砖块）
→ H: s3-encoder  数字键盘编码器（10 键 → 4 位码 + any，与 s3-display 译码器对偶）
→ I: s3-digit-entry 数字输入寄存器（数字码 + 写脉冲 → 8 位 BCD 操作数，换位清除）
→ J: s3-calc     简易计算器（压轴：13 键键盘 → 编码器 → 输入寄存器 → 运算控制 →
                 立即执行链式加减 → 负数 EE → 两位数码管显示）
```

| 新关 | 端口 | 功能 | 教学点 | 参考解 |
|------|------|------|--------|--------|
| **s3-bcd2bin** | bcd[7:0]（十位+个位）→ bin[7:0] | 两位 BCD → 二进制 | 二进制 = 十位×10 + 个位；×10 = ×8 + ×2（移位加权），加法器树合并 | 移位接线 + 3 个 4 位加法器（复用全加器模块） |
| **s3-bin2bcd** | bin[7:0] → bcd[7:0]（十位+个位） | 二进制 → 两位 BCD | double-dabble 加 3 移位算法（左移、≥5 加 3）| 组合展开的加 3 移位网络 |
| **s3-reg-8** | d[7:0] / clk → q[7:0] | 8 位寄存器 | 8 个 D 触发器并排共用时钟——"结果存下来"，计算器的显示屏内存 | 8 个主从 D 触发器 × 时钟并联 |
| **s3-or-chain** | a / b / c / d → y | 多输入或门（4 输入） | 或门原理 = 二极管并联，多输入 = 更多二极管并联（或门级联也能拼）；编码器每条输出码线 = 好几根键线的或 | 4 二极管 + 1 下拉（元件版直接展示） |
| **s3-encoder** | d0-d9（10 键，按钮）→ code[3:0] / any | 数字键盘编码器 | 编码器 = 译码器对偶；一次一键 → 每根输出 = 相关键的「或」= 或门矩阵 | or 矩阵：6×【多输入或门】+ 2×【或门】（8 盒；45 与非门版降为 calcRef 内部元件实现） |
| **s3-digit-entry** | d[3:0] / wr（按钮）/ fresh → q[7:0] | 数字输入寄存器 | 两位 BCD 操作数输入：wr 沿把新数字「左移一位插入」（十位←旧个位），fresh 清十位 | 8 个主从 D 触发器 + 换位接线 + 清除门 |
| **s3-calc** | d0-d9 / plus / minus / eq / c（13 键）→ disp_t[6:0] / disp_u[6:0]（数码管） | 2 位计算器：链式立即执行加减、= 结算、负数显示 EE | 合体：编码器 + 输入寄存器 + 运算控制（标志位/累加器选择）+ ALU + BCD 换算 + 显示 mux + EE 覆写 | 16 盒模块化组装（豁免 29 盒，见关卡设计规范 §一） |

**计算器交互**（真实感，用户已确认的模型）：
- **13 个瞬时按键**：0-9 数字键 + ＋ － ＝ C（全部 button 端口，按住 = 电平 1、松开归 0）
- **立即执行链式**：`12＋5＋` → 按第二个 ＋ 时就算出 17 显示；再按 `3＝` → 20
- **换位输入**：连续按数字键左移插入（`1`、`2` → 12）；运算后按数字 = 新操作数
- **负数**：减法结果 < 0 时显示 `E`（段码 0x79，EE 两位）
- **C 清屏**：清除输入与累加器，回 00
- 显示 = 两个七段数码管（十位 + 个位），结果保持到下次操作

**约束**：2 位 BCD（0-99），溢出截断（99+1 显示 00，向量不覆盖）；EE 后不链式（向量不覆盖）。
