# 拆分设计：元件 → 门 → 模块

> 目标：把玩法拆成三层，**契约（协约）只钉在最底下的元件层**，让玩家从某一章起
> 完全不用再碰元件，直接用「门」搭复杂模块 —— 计算因此变简单。

## 0. 三层阶梯

```
第 0 层  元件 ──► 基础门       ← 只有这一层受契约约束（元件集 / 成本线 / 延迟线）
第 1 层  门   ──► 组合模块     ← 与契约无关：门已经把契约"吃"进去了（契约在门的内部）
第 2 层  模块 ──► 整机         ← 与契约无关
```

一句话原则：**契约约束的是"用哪些元件、元件多贵多慢"，不是"怎么搭电路"。**
门一旦封装好，它的成本和延迟就把契约的差异吸收掉了，上层不必再关心。

## 1. 现状盘点（都已存在，只差菜单没露出来）

| 需要的东西 | 已经有什么 | 位置 |
|---|---|---|
| 契约 = 可用元件集 | `FamilyContract.units`（rtl `npn+res` / dtl `dio+res+npn` / ttl `npn+res+dio` / cmos `nmos+pmos`） | `packages/schema/src/family.ts:26,39` |
| 各契约的**门** | `FAMILY_GATES`（非门 / 与非门 / 或非门 / 与门 / 或门 / 异或门 / 同或门，按契约给不同实现）、`wrapGate()` | `packages/content/src/teachings.ts:109-157` |
| 按契约出全套门 | `teachingModulesFor(family)` | `packages/content/src/teachings.ts:258` |
| 按契约出参考解 | `teachingSolutionOf(levelId, family)` | `packages/content/src/teachings.ts:492` |
| 关卡声明"只能用这些模块" | `moduleAccess: 'none' \| 'all' \| 'listed'` + `allowedModules: string[]` | `packages/schema/src/level.ts:139-141` |
| 判定器执行白名单 | 已在判：`本关只允许使用【…】，不能用【…】` | `packages/compiler/src/judge.ts:145-147` |
| 判定器执行元件白名单 | `allowedUnits` | `packages/schema/src/level.ts:136` |

**唯一的缺口**：门没有进画布库，所以菜单里看不到。
`App.tsx:860` 现在只在「参考解本身用到模块」时才注入门（`teachingStoredFor(spec.family)`），
而 `Palette.tsx` 又把 teaching 模块从「我的模块」里过滤掉了 —— 于是玩家每次都得从元件手搭门。
这正是"太复杂"的来源。

## 2. 顶层菜单：按"层"分章

| 章 | 玩家用什么 | 关卡字段 | 契约菜单 |
|---|---|---|---|
| 第 0 章 · 元件与门 | 只给元件，手搭门 | `moduleAccess: 'none'` | **显示**（可换 rtl / cmos / ttl / dtl） |
| 第 1 章 · 用门搭模块 | 给一组基础门 | `moduleAccess: 'listed'` + `allowedModules` | 隐藏 |
| 第 2 章 · 用模块搭整机 | 给自己的模块（封装玩法） | `moduleAccess: 'all'` | 隐藏 |
| 第 3 章 · 时序 | 同上 + 时钟关 | 同现状 | 隐藏 |

每章开头一句"本章只用什么"，把"契约只作用在元件层"讲成世界观，而不是藏在代码里。

## 3. 关卡内的菜单：左侧面板三个区（第一步要做的改动）

```
┌ 我的元件    可用 2/6        ← ① 受契约约束（复杂关默认收起）
│   三极管 NPN   价格 2
│   基极高电平导通 ···  延迟 1.0 ns
├ 基础门      本关 3 个       ← ② 新建：本关提供的门（teachingModulesFor）
│   与非门       成本 10
│   2 入 / 1 出 ·····  延迟 2.5 ns
├ 我的模块    12 个           ← ③ 现状：自己封装的
│   半加器       成本 60
│   1 入 / 1 出 ·····  延迟 6.5 ns
```

- ① **我的元件**：只有这一区受契约约束。复杂关整区收起 —— 从第 1 章起玩家根本不用看元件。
- ② **基础门**：新增区，内容 = 本关允许的门（`allowedModules` 过滤后的
  `teachingModulesFor(family)`），卡片复用现有模块卡样式（成本 + 延迟 + 入/出），
  拖放或"点击选中 → 点画布"都可用。逻辑版口径下不显示延迟（沿用现有 `mode` 开关）。
- ③ **我的模块**：不变。
- **默认展开策略**：关卡声明默认展开哪一区（如 `openSections: ['gates']`），
  第 1 章进来只展开②、①收起。`useOpenSections` 已存在，加默认值即可。
- **契约菜单**（`FamilyPicker`）：只在第 0 章出现，其余章节隐藏。

## 4. 连带的数值改动（不能漏）

允许用门之后，参考解会比手搭更省 —— 现有的 `budgetHalf` / `optimalHalf` / 延迟预算必须
按**门版参考解**重标，否则成本线和延迟线会失真。

- 参考解：`teachingSolutionOf(levelId, family)` 已支持按契约出解，再加"门版参考解"。
- 成本线 = 门版参考解成本 ×2（沿用现有口径）；延迟预算 = 门版参考解实测延迟 ×2
  （沿用现有口径，见 `levels-ari.ts` 里 52 ns / 76 ns 两处的做法）。
- **门要收钱**（= 其内部元件成本，例如非门 6 元）。不收钱则"成本最优"这条核心玩法失效。
- **判定器零改动**：模块是编译期内联的，成本/延迟照算；逻辑版 / 时序版开关同样适用。

## 5. 一期最小可玩（实施顺序）

1. **菜单分区**：①元件 ②基础门 ③我的模块 + 分区默认展开策略。
2. **注入门**：关卡 `moduleAccess !== 'none'` 时把本关允许的门注入画布库。
3. **一关示范**：「用门搭半加器」（`moduleAccess: 'listed'`，参考解只用门）。
4. **重标该关成本线 + 延迟预算**（先量后改）。
5. 通了再铺第 1 章（8–10 关）与其余章节。

## 6. 已拍定的三个选择

1. **第 1 章先给三个门**：非门 + 与非门 + 或非门；其余门（与门 / 或门 / 异或门）按关卡逐步给。
2. **第 0 章（手搭门）只留 3 关**：非门 / 与非门 / 或非门各一关，别让玩家手搭十个门。
3. **门允许展开内部电路**（双击模块已有的能力）：保留"门是元件搭的"这层可见性，
   避免门变成黑箱。

## 8. 实施记录：第 1 步已完成（菜单分层 + 注入门）

### 8.1 核实到的事实（都是实测，不是推断）

- **现有关卡里 23 处是 `moduleAccess: 'all'`、8 处是 `'none'`**（27 关主线 + 支线/教学）。
  → 本次合并后，那 23 关**立刻**能在菜单里用门；第一章的手搭关（`'none'`）维持不给门。
- **`teachingModulesFor(family)` 返回的不是"基础门"**：rtl 的 18 个里混着
  全加器(90 元)、七段译码器(430 元)、二进制→BCD(3084 元)、显示控制(1500 元)、运算控制(1486 元)…
  这些是「一键出答案」用的**复合积木**，列进元件库菜单等于把答案摆在玩家面前
  （BCD 关的答案本来就是「二进制→BCD」）。
  → 菜单必须按 `BASIC_GATES`（content 已导出）过滤，并有测试守死这一条。
- **门价目 = 手搭成本，这不是巧合是标定**：
  - 非门（rtl）6 元 = NPN 2 元 + RES 2 元 × 2；
  - 非门（rtl）1.5 ns = R1 500 ps + Q1 1000 ps，与 s1-not 参考解的关键路径一致。
  → **门不会让现有的成本线/延迟预算失效**，两条线不必重标 —— 原先担心的"数值重标"这一项
    可以划掉。真正需要单独看的是**门族之间的差异**（cmos 非门 2 元 / 1.4 ns，比 rtl 便宜且快），
    那正是契约该有的差异，属于设计预期。

### 8.2 已完成

  逻辑版口径下不显示延迟。
- 注入：进关时把本契约的门并进画布库（`App.withLevelGates`），且 `docFor` 经
  `resolveMissingModules` 剪库后由 `withProvidedGates` 把门补回（session.ts）。
- **端到端已真实验证**（`apps/studio/test/palette-gates.test.tsx` 两条）：
  ① `'all'` 关卡（半加器）里出现「基础门（…）」区，且查不到复合积木；
  ② `'none'` 关卡（第一章）里不出现「基础门」区。

  "产品端到端没通"。
